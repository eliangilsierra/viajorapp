# Viajorapp brand strategy

Status: draft for owner review (concept stage, 2026-10-27). Author: brand and visual identity design.
Companion assets: [`design/brand/`](../../design/brand/) (three concepts, gallery, QA report).

**Final brand approval belongs to the project owner.** The recommendation in section 10 is a reasoned
suggestion, not a decision, and it is reversible (section 11): no product code depends on a concept yet.

How this was made: every mark is hand-authored vector geometry (generated by the Python scripts in
`design/brand/tools/`) and rendered locally with resvg. No image-generation service, no network model,
no remote design tool and no third-party asset was used. The wordmark is drawn outlines, not a font.

## 1. Purpose and promise

**Purpose.** Help people plan trips they own: a plan that lives on the traveller's device, works with no
signal, and uses maps, AI and sync only when the traveller asks.

**Promise (the tagline).** *Plan smarter. Travel further.* Smarter means fewer tools, fewer
re-entries and suggestions you can see before they change anything. Further means the plan keeps working
where the network does not.

**Brand promise in one line for a user:** "Your trip stays yours, and it works wherever you go."

## 2. Mission and vision

- **Mission.** Build an open-source, offline-first travel planner that keeps all trip data on the
  device by default, with every cloud, map-download, AI or sync feature optional, explicit and
  reversible.
- **Vision.** Planning software that a traveller can trust the way they trust a paper map: it is
  theirs, it does not report on them, and it still works when everything else fails.

## 3. Audience

Drawn from the personas in [`docs/product/PRD.md`](../product/PRD.md):

| Audience | What they want from the brand | What breaks trust |
| --- | --- | --- |
| Independent multi-city travellers | Calm, precise planning | Booking upsells, cluttered screens |
| Couples and small groups who plan together | Shared plans without a mandatory account | "Synced" that is not |
| Off-grid and low-data travellers | A plan and a map with no signal | Hidden downloads, background traffic |
| Spreadsheet planners | Import without retyping | Lock-in |
| Privacy-aware users who still want AI help | Suggestions with their own key, shown first | AI that edits silently |
| Open-source contributors and reviewers | A credible, documented, reproducible project | Ad hoc design, unlicensed assets |

Primary languages at 1.0 are English and Spanish (PRD I18N-01), so the brand must work in both and must not
rely on an English-only wordplay.

## 4. Personality and tone of voice

**Personality.** Capable, calm, candid, curious. Like an experienced travelling companion who never
pushes: it prepares, it explains, it steps back.

| We are | We are not |
| --- | --- |
| Clear and concrete | Vague or hyped ("revolutionary", "AI-powered everything") |
| Honest about state ("Saved on this device", "Needs a connection") | Reassuring when it is not true |
| Warm in small touches | Cute, jokey, or gamified |
| Respectful of choices ("Add", "Skip") | Pushy or guilt-based |
| Technical when helpful, plain by default | Jargon-first |

**Voice rules.**

1. Say where data is and who controls it, in plain words ("Stored on this device").
2. Optional means optional: label suggestions and network features as such, and make the default no.
3. Prefer verbs and facts to adjectives. No exclamation marks in product UI.
4. Never imply a connection, a sync or a route that does not exist.
5. Same voice in English and Spanish; translate meaning, not slogans.

Examples:

| Instead of | Say |
| --- | --- |
| "We've optimised your trip with AI!" | "Suggestion (optional): add a sunset viewpoint near Day 2. Nothing changes until you tap Add." |
| "You're all synced!" (when not) | "Not synced. Your plan is safe on this device." |
| "Unlock premium offline maps" | "Download this region (84 MB) to use it without a signal." |

## 5. Differentiation versus conventional travel planners

| Dimension | Conventional planners | Viajorapp |
| --- | --- | --- |
| Data location | Vendor servers, account required | On the device by default, no account |
| Connectivity | Online first, offline as a premium add-on | Offline first, network as an option |
| Business model signal | Booking, ads, affiliate links | Open source (MIT), no booking, no telemetry by default |
| AI | Built in, opaque, on by default | Optional, bring-your-own-key, shown before it changes anything |
| Visual language | Planes, globes, pins, sunsets, stock photography | A distinctive abstract mark, restrained palette, real information |
| Tone | Aspirational, upselling | Practical, candid |

Category visual clichés to avoid: aeroplanes, globes, plain location pins, compasses, suitcases, palm
trees, stock beach photography, cartoon mascots, emoji as icons.

## 6. Brand attributes

1. **Owned**: the traveller holds the data and the choices.
2. **Dependable**: works without signal; states what it knows and does not know.
3. **Open**: open source, documented, reproducible design.
4. **Curious**: made for wandering, with room for the unplanned.
5. **Considerate**: optional help, no pressure, accessible by default.

## 7. Visual principles

1. **One idea, few shapes.** The mark is built from two to four primitives and is nameable in a sentence.
2. **Reads small, reads flat.** Identifiable at 16 px and in one colour before it is decorated.
3. **Two colours at most in the mark.** One brand colour plus one accent that has a job (destination,
   optional suggestion), never decoration.
4. **Accessible by construction.** Text pairs 4.5:1, graphics and component boundaries 3:1, meaning never
   carried by colour alone.
5. **Calm density.** Generous spacing, clear hierarchy, real content instead of illustration.
6. **Dark mode is a first-class variant**, with its own mark colours, not an inversion.
7. **Honest imagery.** No fake screenshots, no stock photography implying features; concept screens are
   labelled as illustrations.
8. **Reproducible.** Every asset is generated from code behind design tokens; no hand-edited binaries.

## 8. Naming and typography conventions

**Name.** `Viajorapp`: capital V, rest lowercase, one word, no space, no hyphen. Never `ViajorApp`,
`VIAJORAPP` in running text, or `Viajor App`. The name nods to *viajar* (Spanish, "to travel"); it is
used as a name, not translated. Package and repository identifiers stay lowercase (`viajorapp`).

**Tagline.** *Plan smarter. Travel further.* Two sentences, full stops, sentence case. Not part of the
logo lockup; set in body type below or beside it. Spanish tagline to be agreed by the owner (not
invented here).

**Logotype.** Hand-drawn geometric outlines (no font dependency). Do not re-typeset it in a font.

**Typefaces (UI and documents).** At most two open-licensed (SIL OFL) families per product surface,
bundled as Compose Multiplatform resources. Each concept proposes a pairing in its `typography.md`:
Manrope with Inter, Space Grotesk with IBM Plex Sans, or Fraunces with Source Sans 3. Licence text must be
re-checked at bundling time; no font file is in the repository at this stage.

**Scale and accessibility.** Body 16 sp minimum for long text, 200 percent font scale must reflow without
clipping, tabular figures for dates, times, distances and prices.

**Clear space and minimum size (provisional, to confirm in the production phase).** Clear space equals the
diameter of the destination node of the chosen mark. Minimum symbol size 16 px digital; minimum lockup
height 24 px.

## 9. How the brand communicates the five pillars

| Pillar | In the mark | In colour | In UI and copy |
| --- | --- | --- | --- |
| Offline-first | Nothing implies a signal, cloud or antenna | Calm deep tones, no "connected" green or blue badges | "Offline ready" chip, "Stored on this device", downloads sized and explicit |
| Local data ownership and privacy | One continuous line, closed shape or lock-and-road, never an outbound arrow | Deep brand colour dominates; accent is small | States where data is; no tracking language; "Not synced" is shown honestly |
| Freedom | Open ends, a road, open terrain | Warm accent reserved for choices | Skip and Add are equal weight; defaults are no |
| Exploration | Route, road to horizon, summit | Accent marks destination and discovery | Empty states invite, they do not nag |
| Intelligent but optional planning | Accent on a single element, so suggestions can borrow it without becoming the logo | Accent only on optional items | Dashed "Suggestion, optional, on device" cards; nothing changes until confirmed |

## 10. Evaluation rubric, scoring and recommendation

### 10.1 Rubric

Each criterion is scored 1 to 5 (5 is best) and weighted; the total is out of 100.

| Criterion | Weight | What a 5 means |
| --- | ---: | --- |
| Recognition | 15 | Memorable, nameable in one sentence, recalled after one sighting |
| Simplicity | 10 | Few shapes, one idea, no decoration |
| Scalability | 15 | Identifiable at 16 px and in one colour; holds up large |
| Distinctiveness | 15 | Unlike travel, map and security category defaults; low confusion risk |
| Accessibility | 10 | Contrast pairs pass, no red and green reliance, shape carries meaning |
| Reproducibility | 10 | Rebuildable from primitives; trivial to convert to VectorDrawable or Compose Path |
| Mobile suitability | 15 | Fills the Android adaptive-icon safe zone and sits centred under circle, squircle and rounded masks |
| Cross-surface consistency | 10 | The same mark and tokens work on app, store, web, README, print and embroidery |

Weighted total = sum(score x weight) / 5.

| --- | ---: | ---: | ---: | ---: |
| Recognition | 15 | 4 | 4 | 3 |
| Simplicity | 10 | 5 | 4 | 3 |
| Scalability | 15 | 5 | 4 | 3 |

The scores are the designer's judgement after viewing the renders and running the checks in
[`design/brand/concepts/QA_REPORT.md`](../../design/brand/concepts/QA_REPORT.md). They are an
input, not a measurement; per-criterion reasons are in each concept README and in the gallery. Evidence
used: contrast ratios computed from the palettes, heuristic detail-loss at 16 to 48 px, centring and margin
checks, an independent safe-zone measurement (all three icons sit about 7 px inside the 312.9 px radius of
the 66 dp circle at 1024), mask previews, and a visual review of the legibility sheets.

### 10.3 Recommendation

> **Decision (2026-10-27):** the owner chose Concept 01, Waypoint, after reviewing the gallery. Concepts 02
> and 03 stay in the repository as records of the exploration. The decision is a design judgement, not the
> result of user testing or a trademark search; both remain open (see section 12).

**Recommended: Concept 01, Waypoint (87.0 / 100).** A V drawn as a route from a hollow origin to a solid
destination.

Why:

- **Best at what a mobile icon needs.** It is the simplest mark, remains legible at 16 px in colour and in one
  colour, and its bold silhouette fills the adaptive-icon safe zone under every mask.
- **It carries the name.** The V ties icon to *Viajorapp* and supports a lockup that reads at a glance.
- **Discipline for the accent.** The accent colour has a single job (destination), which maps directly to
  "optional suggestions" in the UI.
- **Cheapest to build and maintain.** Three primitives, trivially a Compose Path.

What it costs (be clear-eyed):

- **Distinctiveness is its weakest score (3 of 5).** V marks and route-with-nodes glyphs are common, so
  the mark is ownable mainly through its asymmetry and palette. Mitigations: keep ring versus disc, keep the
  teal and amber pairing, and consider a custom V terminal in the production phase.
- Amber on a light background is 4.2:1, so it is graphics-only and never carries text.

**Runner-up: Concept 02, Keyhole Road (80.0).** Choose it if the owner wants privacy to be the visual
hook and accepts the security-category confusion (password managers, VPNs). **Concept 03, Contour (63.0)**
has the strongest terrain character but fails at small sizes and has an unintended "eye" reading that is
unhelpful for a privacy-first brand; it would need a simplified small-size cut before it could be reconsidered.

What would change the recommendation: a user test in which Waypoint is read as "generic navigation" by
most participants (then Keyhole Road moves up); a trademark search finding a close V-and-route mark in
mobility or travel classes (not performed here); or the owner deciding that distinctiveness outweighs
scalability (weights in 10.1 are adjustable).

## 11. Reversibility and design tokens

The choice is reversible because nothing downstream is built on a concept yet and the assets are designed to
sit behind tokens:

- Colours exist as named tokens (primary, on-primary, accent, on-accent, bg, surface, text, text-muted,
  outline) in light and dark, in each concept's `palette.json`. UI code should reference tokens only.
- The mark exists in four files per concept (`symbol`, `symbol-dark`, `symbol-mono`, `app-icon`) plus
  lockups; swapping the brand means replacing those files and the token values.
- Compose Multiplatform theme, launcher icons, store listing and README header should each read from a single
  source (token file and one mark set), so a rebrand is a data change plus a regenerate, not a refactor.
- Suggested follow-up for the engineering side: generate `BrandColors.kt` and a CSS token file from the
  chosen `palette.json` (the local-logo-brand-design skill ships a tokens script for this).

Nothing in `design/brand/` is referenced by build files, so removing a concept deletes no behaviour.

## 12. Provenance, licensing and limits

- **Authorship.** Marks, wordmark, palettes and mock screens were authored as code by the brand designer
  (an AI assistant working under the owner's instructions); they are original constructions, not traced from
  any existing logo. Licence for brand assets is to be set by the owner (the repository is MIT; trademarks and
  logos are often licensed separately).
- **Fonts.** None embedded. Proposed families are SIL OFL 1.1 according to their upstream listings; verify
  before bundling. Mock UI PNGs were rendered with system fallback fonts (Segoe UI, Georgia) and are
  illustrations only.
- **Tools.** Python 3.12 (stdlib and Pillow), resvg, and the QA scripts of the installed
  visual-asset-quality-review skill. No network access and no image model.
- **Not done.** No trademark or design-patent search; no user research; no device testing; no svgo
  minification, VectorDrawable or iOS asset catalogue export yet; colour-blind behaviour reasoned, not
  simulated. Lookalike lists are the designer's judgement.

## 13. Next steps once the owner picks a direction

1. Owner decision recorded in an ADR or the PRD open questions.
2. Production pass on the chosen mark: refine junctions, outline strokes, a custom V terminal if Waypoint,
   small-size cut if Contour.
3. Generate tokens (`tokens.json`, `BrandColors.kt`, CSS) and the full icon set (Android adaptive with
   monochrome layer, iOS 1024 with dark and tinted variants, Play 512, favicon) with the mobile-app-icon
   production workflow, then run the completeness and safe-zone checks again.
4. Write brand guidelines: clear space, minimum sizes, misuse list (stretching, recolouring, light mark on dark
   backgrounds, effects), and the Spanish tagline.
5. Agree the asset licence and run a trademark search before public launch.
